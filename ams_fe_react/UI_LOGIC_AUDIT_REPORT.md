# UI & Logic Audit Report: Angular to React Migration

This report summarizes the discrepancies and audit findings between the original Angular project (`ams_fe`) and the new React project (`ams_fe_react`).

## 1. Executive Summary
The migration of the Attendance Management System (AMS) to React 19 is approximately 70% complete. Core features (Auth, Dashboard, Attendance) show high UI parity. However, significant discrepancies exist in API pagination logic and prefixing, as well as a large gap in unmigrated modules.

## 3. Technical Observations

### API Pagination (0-based vs 1-based)
- **Attendance Daily**: Consistent 0-based (React and Angular).
- **Departments**: Consistent 0-based (React uses `page - 1`).
- **Employees**: **Inconsistent**. React `employeeApi` currently passes the raw UI page number (starting at 1) to `/employees/page`. Angular's `EmployeeService` also does this, but usually Spring Data backends expect 0. This requires verification of the specific backend endpoint for Employees.

### `axiosInstance` Integration
- All React features successfully use the centralized `axiosInstance`.
- Some reactivity (loading states, success/error alerts) in React is more robust due to `TanStack Query` and `useMutation` patterns compared to Angular's manual `Subscription` and `finalize` blocks.

### CSS Parity
- Angular used Tailwind v4 classes globally. React mirrors these class names, ensuring visual parity. Discrepancies are minor and mostly related to spacing and transitions handled differently by CSS Modules vs Angular component scoping.

---

## 4. Recommendations
1.  **Standardize Pagination**: Unify all APIs to use either `page - 1` (UI to Backend) or ensure Backend is configured for 1-based paging.
2.  **Fix Endpoint Prefixes**: Ensure all HRM endpoints (like `/positions`) consistently use the `/v1` prefix if required by the backend.
3.  **Implement Actual Audit Log**: Replace hardcoded mocks in `admin.api.ts` with real `axiosInstance` calls once backend endpoints are available.
4.  **Complete Missing Modules**: Prioritize the migration of `Payroll` and `Reports` to achieve full feature parity.
